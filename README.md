# 初冠雪ごよみ（kansetsu-koyomi）

気象庁が全国 44 山で記録してきた**初冠雪日 4,105 行（1873–2026 寒候年）**を読む静的サイト。

初冠雪は「山が白くなった日」ではなく、**気象台からそう見えた日**である。
本サイトは記録をそのまま出すと同時に、その定義を画面に書く。

**目視による初冠雪の観測は 2026 寒候年で終わった。** 2027 寒候年からは解析積雪深による
「山頂における積雪の状況」に置き換わっている（気象庁, 2026-07-31 公表）。
最後の目視記録と、最初の計算された今季を、分けたまま並べている。

## 画面

| 経路 | 中身 |
|---|---|
| `/` | 今日の山 — 44 山を気象庁の一覧順（北の官署から南へ）に並べ、今季の状態で塗り分ける |
| `/mountain/{code}/` | 山ごと — 全期間の折れ線・平年値・最早・最遅・分布・全記録 |
| `/trend/` | 遅くなっている — 事前登録した主張と、帰無モデル・対照・測って捨てた話 |
| `/table/` | 表とデータ — 44 山の要約表と JSON / CSV の配布 |
| `/about/` | 観測の定義 — 気象庁の原文、寒候年、記号、富士山の例外、確かめたこと |

## 作り

```
etl/fetch.py     気象庁 → raw/（raw は配らない）
etl/build.py     raw/ → data/*.json（前提が崩れたら例外で止まる）
data/            出荷する成果物。git にコミットする
app/             Next.js（output: export・関数実行ゼロ）
tests/           pytest — 品質ゲート G-01..G-12
tests-js/        vitest — 暦・図の骨格・フッタ規約
harness/smoke.mjs 実ブラウザ検品（明暗 2 テーマ × 5 画面 + 4 幅 = 122 項目）
```

## 使い方

```bash
npm install
npm run data      # 気象庁から取得して data/*.json を作り直す
npm run data:latest  # 今季の表(S-2)だけ取り直す
npm run verify    # typecheck → vitest → pytest → build → 実ブラウザ検品
npm run dev
```

`npm run data` は raw/ にあるものを再利用する。取り直すなら `cd etl && python fetch.py --refresh`。

## 主張

**初冠雪は遅くなっている —— 条件を満たす 33 山に例外がない。**

1967 寒候年以降、窓の中に `--`（その寒候年に冠雪が観測されなかった年）を持たず、
30 年以上の記録がある 33 山すべてで線形の傾きが正。中央値 +14.0 日 / 100 年。
帰無モデルは**全山に同じ年ラベル置換**を当てるもので、山どうしの相関を保ったまま
傾きだけを壊す。2,000 回のうち 33 山そろったのは 1 回（p = 0.0010）。

崩れうるところも同じ画面に置いてある —— 除外した 11 山を打ち切って戻すと 36/44 で
8 山の符号が変わり、推定量を Theil–Sen にすると 1 山の符号が変わる。
そして、これは「雪が降った日」ではなく「記録」の傾きである。

### 測って捨てた主張

- **「平年より遅い」は多数派のはず** → 平年日より遅かった年は 44 山平均 47.8%、
  半数を超えた山は 10 山。**不成立。** 富士山だけが歪んでいた
- **見る場所が変われば日付が変わる** → 富士山を河口湖・三島と統計期間を揃えて比べて
  1〜2 日。効果はあるが単独の主張にするには小さいので、解説の一節に格下げ
